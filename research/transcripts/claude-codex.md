# Passive transcript reads: Claude and Codex

Produced by GPT-6 Astra in the driving Codex session on September 11, 2026, for [Verify passive transcript reads for Claude and Codex](https://github.com/dungle-scrubs/harness-cli-normalizer/issues/155).

## Finding that changes the next decision

**Observed for Claude; documented in source for Codex:** both have a native read API, but neither API is a lossless export of every retained record. Claude's SDK selects one message chain and filters records. Codex returns reconstructed turns and items, applying rollback to that view. HCN cannot equate either response with all retained history or with original records. The next decision must specify which native source is authoritative for each requested read. [Claude probe](claude-read-probe-result.json), [Claude SDK 0.3.233](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.233/sdk.mjs), [Codex rollback projection](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server-protocol/src/protocol/thread_history.rs#L1318-L1342).

**Documented in source:** one Codex file is not necessarily the whole saved conversation. Its local store distinguishes legacy history from paginated history; a paginated rollout may hold only a suffix, with display metadata in SQLite. **Inference:** accepting a file path does not by itself establish complete-history coverage. [Local store reads](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/thread-store/src/local/read_thread.rs#L32-L99).

This resolves research facts, not the HCN ownership decision or Trevor's ownership ticket. No production implementation was made.

## Claude evidence

**Documented:** the owning documentation describes disk session functions as file operations and distinguishes reading messages from resuming a model. The selected SDK declaration says it reconstructs a chain through parent links, returns chronological messages, optionally includes system messages, and accepts offset/limit. [Official session browser guide, "Read a session's messages"](https://platform.claude.com/cookbook/claude-agent-sdk-05-building-a-session-browser), [SDK 0.3.233 declarations, `getSessionMessages`, `GetSessionMessagesOptions`, `SessionMessage`, and `getSubagentMessages`](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.233/sdk.d.ts).

**Documented in distributed source:** in the selected `sdk.mjs`, `OOt` delegates local reads to `gK`; `gK` locates and reads the file; `jPe` selects a chain; `BPe` filters records; `MA` constructs the returned shape; `NA` slices it. `FPe` skips malformed lines. `zPe` uses the pre-compaction skipping reader for files over 5,242,880 bytes unless its disabling setting is active. That reader recognizes the compaction marker near the start of the line. These are internal symbols, not supported import contracts. [Exact distributed SDK](https://unpkg.com/@anthropic-ai/claude-agent-sdk@0.3.233/sdk.mjs).

**Observed:** the [probe](claude-read-probe.mjs) creates 8 synthetic records plus 1 malformed line in an isolated configuration directory. The default result contains 4 message records from the selected branch. Enabling system messages adds the notice but not the attachment. The abandoned answer, unknown record, `parentUuid`, and extra field remain absent. Both a missing conversation and an invalid ID produce an empty array. [Captured result](claude-read-probe-result.json).

**Observed:** two synthetic compaction cases use the same message chain. The 1,380-byte input returns both earlier messages. The 6,292,772-byte input returns the boundary, summary, and later answer, omitting the earlier messages. The probe puts the compaction subtype near the beginning of its line, as required by the selected reader's bounded scan. An initial fixture with the subtype later in the line did not trigger skipping; that fixture construction was corrected before capturing the final result. [Probe and assertions](claude-read-probe.mjs), [captured IDs and sizes](claude-read-probe-result.json).

The probe uses an empty process environment with only an explicit executable path and isolated `CLAUDE_CONFIG_DIR`. It does not load real transcripts, credentials, hooks, or extensions. It blocks common JS process creation, network calls, and file mutations during the read. Source fingerprints match before and after. This is bounded evidence for this SDK file-read operation, not proof about arbitrary native code, remote session stores, every filesystem call, or a concurrently active writer.

## Codex evidence

**Documented:** the selected app-server README defines `thread/read` and the experimental turn/item pagination methods. Its wire contract includes native cursors and item detail selection. **Documented in source:** the read processor parses a thread ID, reads the store, and builds the API view. [Versioned README, read example and following pagination sections](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server/README.md#L534-L590), [wire types](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L1470-L1583), [read processor](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server/src/request_processors/thread_processor.rs#L2275-L2520).

**Documented in source:** when a loaded paginated thread is read with turns, `apply_thread_read_store_fields` calls `persist_thread` before loading the turns. This is a specific counterexample to treating every native read as mutation-free. The unloaded case follows a different path. The behavior of a newly spawned app-server, all startup services, and every storage backend was not runtime-verified here. [Loaded read persistence](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server/src/request_processors/thread_processor.rs#L2476-L2508).

**Documented in source:** rollback removes turns from the legacy display view; the persisted rollback record and earlier retained lines are not returned as an abandoned branch by that view. The rollout reader accepts retained response items, compaction and metadata records, and reports a parse-error count internally. Some transient events are deliberately not persisted. Therefore neither the API nor a raw file can be described as a recording of everything that ever happened. [Rollback projection](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server-protocol/src/protocol/thread_history.rs#L1318-L1342), [rollout reader](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/rollout/src/recorder.rs#L981-L1055), [persistence policy](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/rollout/src/policy.rs#L8-L145).

**Documented in source:** local reads verify a rollout's thread identity before trusting a stored path; paginated metadata and history are distinct from legacy file-backed history. Thread items encode tool results and media-specific fields, but the read API does not return each original line or unknown raw field. [Local source checks](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/thread-store/src/local/read_thread.rs#L101-L161), [item types](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L226-L399).

**Documented in upstream tests, not observed in this session:** read tests cover stored/archived threads, loaded threads, stores without rollout paths, pagination, and a cursor whose anchor was removed by rollback. The last case expects an explicit invalid-cursor error. [Selected test suite](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server/tests/suite/v2/thread_read.rs#L101-L299), [cursor invalidation test](https://github.com/openai/codex/blob/be6e8eac029b183056b7e4402879f15d2c85f61b/codex-rs/app-server/tests/suite/v2/thread_read.rs#L1080-L1146).

## Limits and evidence needed next

- **Unverified:** passive startup of a selected Codex app-server under all relevant settings and backends. Before choosing that read method, use isolated synthetic state, disabled external integrations, a blocked model endpoint, source fingerprints, and filesystem/network observation. A loaded-thread flush must not be advertised as a no-write operation.
- **Unverified:** a stable read boundary under active append, incomplete final lines, replacement, compression, truncation, or native cleanup. The contract ticket must choose an explicit failure/restart rule, then test each selected method.
- **Unverified:** full media payload availability, externally stored tool results, subagent-file coverage, and complete fork trees. Preserve references and report absence; do not infer recoverability from a text-only example.
- **Unverified:** a public, version-stable raw export that meets the entire charter for either harness. The investigated native APIs are narrower. A direct source reader remains a candidate, with versioned parsing and explicit source-coverage checks; it has not been designed or implemented here.
- **Next human decision:** define the read source and original-record meaning using these differences. The research does not authorize silently narrowing full history to a display view, adding a consumer index to HCN, or following related conversations beyond the one requested.

All ticket areas are covered above as documented, observed, or explicitly unverified. No real private transcript or model prompt was used in the probes.
