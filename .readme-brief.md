- Problem (confirmed): Each coding-agent CLI has its own interface, so using more than one is inconvenient.
- Occasion (confirmed): You have an agent that hands work to other coding agents, and you want it to learn one tool and use it well instead of learning each CLI.
- Incumbent (confirmed): The calling agent or script translates every request setting itself (tool or skill limits, sandbox, read-only, private, context window) into each harness's flags, and each harness spells a setting differently, supports it partly, or lacks it.
- Value (confirmed): You pick the harness and model that suit the task and your preferences, and send the same request whichever one runs it.
- Non-goals (confirmed): hcn is not a harness itself. It adds a layer between the caller and the harness, which some users will not want. It supports some harnesses, not all of them, though more may come.
