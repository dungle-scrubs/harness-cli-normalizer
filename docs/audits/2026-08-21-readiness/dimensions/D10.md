## Findings

### F-D10-1 `test/interpretation/purity.test.ts:11-21`

- question: Q1+Q2
- severity: minor
- coverage: `no_recorded_issue`, `metadata_match`
- failing scenario: a future change adds `import "node:fs";`,
  `import fs from "fs";`, `process.argv`, `process.cwd()`,
  `performance.now()`, `fetch(...)`, `crypto.randomUUID()`, or `Bun.env` to
  a file under `src/interpretation` or `src/knowledge`. The `IMPURITY`
  regex matches none of them, `tsc --noEmit` exits 0, and `pnpm lint` exits
  0 or emits an `info`. The layer stops being pure and both `pnpm check` and
  CI stay green, so a consumer that imports a descriptor in a browser or a
  worker breaks at runtime with no gate having fired.
- evidence: `SCRATCH/audit/bypass/regex-results.txt` (P1-P11 all
  `purity=passes`); `SCRATCH/audit/bypass/tsc-out.txt` empty with
  `tsc exit=0`; `npx biome check` on `probe3.ts` -> `Found 1 info.`,
  `exit=0`. Full table in `SCRATCH/audit/D10-bypass-candidates.md`. No
  violation exists in the tree today: `grep -rnE
  'process\.(argv|cwd|platform|version|exit|kill|hrtime)|globalThis|
  performance\.now|\bfetch\(|new Date\(|crypto\.|Bun\.env|^import
  ["'\'']node:' src/interpretation src/knowledge` returns nothing. The
  severity is `minor` under the D10 rubric for that reason.
- smallest change that flips it to pass: replace the regex list in
  `IMPURITY` with an allow-list scan - reject any `import`/`export` whose
  specifier is not a relative path, and add arms for `\bprocess\.`,
  `\bfetch\(`, `\bperformance\.`, `\bcrypto\.`, `\bBun\.`, `\bnew Date\(`,
  `\bglobalThis\b`. Alternatively enable `correctness/noNodejsModules` in
  `biome.json` with an override scoped to those two directories.
